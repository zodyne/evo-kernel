# 运动链路的自检必须取非零速度点，补偿后先核对 R̂/v 守恒再采信 dB

## 主张

所有运动相关量在 v=0 上恒为恒等：走动量 0 bin、走动峰值损失 `+0.00 dB`、耦合项 `v*f0/μ = +0.0000 m`、两条处理路径（有走动 / 去走动）打印出的峰位与峰值完全相同。**所以拿静止/零速用例给运动链路做自检没有判别力**——正确的自检是取非零速度点（最好覆盖 v_max 附近），并且对补偿类路径先做守恒检查：补偿后的 `R̂` 要落回目标真值、峰值不应比未补偿低一个数量级。这两项过不了时，它打印的 dB 数（"损失"/"增益"）不可采信，先查实现。

## 为什么

走动补偿是「把逐帧迁移的目标能量对齐回同一距离门」的操作，做对了峰值应当提升（或至少不塌）、`R̂` 不应跳变；而在 v=0 时走动为零，补偿退化为恒等操作，退化/写错的补偿分支与正确分支输出完全一致——零速用例天然对这一类缺陷全绿。

## 证据（切片命令 ↔ 结果）

- 扫速探针的 v=0 行（两条路径打印值完全相同）：
  `v=  0.0: 走动 peak=2.3121e+05 R= 99.681 v= +0.000 | 去走动 peak=2.3121e+05 R= 99.681 v= +0.000 | 损失= +0.00 dB | 0.000 bin v= …`
- 单 chirp 探针 v=0 行（耦合项恰为 0）：
  `单 chirp（第 0 个 chirp，目标起始 R=100.000）读数:   v=  +0.0 m/s -> R̂= 99.9723 m   偏差=-0.0277 m   v*f0/μ = +0.0000 m   ΔR=0.7495 …`
- 同一实验在非零速度点（v=-9.886 m/s）上两条路径彻底分叉，且报出 32 dB：
  `有走动  : peak=2.4295e+05 R=101.180 v=-9.886 去走动  : peak=5.8063e+03 R=18.737 v=-11.406 => 本代码实测的走动峰值损失 = +32.43 dB  range 剖…`
  ——同一目标两条路径的 `R̂` 相差 82.4 m（101.180 vs 18.737）、峰值相差约 42 倍：至少一条路径是错的，此时挑任何一条的 dB 当物理结论都不成立。
- 项目参数（用于复现该走动量）：`T_frame=7.680 ms  dR=0.7495 m  walk@55=0.4224 m = 0.5636 bin  T_ramp=51.2 us`。

## 边界 / 反例

- 本条不主张「零速用例无用」：静止场景本身要用它；主张的是**它不能作为运动链路的唯一/尾部自检**，且必须与非零速度点配对。
- 非零速度点的取值要覆盖目标可能出现的量级：低速点若走动远小于 1 bin，同样可能看不出实现缺陷（本会话的非零速度点是 v=-9.886 与 v≈55 m/s，其中后者单帧走动 0.5636 bin）。
- 测试若比较的是「补偿 vs 不补偿」两套仿真场景（而非两条处理路径），守恒检查改成：两条场景的真值 `R(t)` 已知且不同，不能拿互为参照。

## 失败信号（未来命中即该想起本条）

- 想用 v=0 的 `损失= +0.00 dB` / 两条路径读数相同来宣布补偿实现正确。
- 补偿实验打印出 `R̂` 与真值差几十米、或峰值掉一个数量级，而报告里只引用了它给出的 dB 数字。
- 自检用例全绿，但同一份代码在非零速度点上从未被跑过。
