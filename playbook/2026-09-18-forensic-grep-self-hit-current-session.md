# 跨文件搜『谁提到过 X』必然自命中：执行这次搜索的会话自己会进结果集

## 主张

在会话/日志目录里用子串搜"谁提到过 X"（`rg -l 'X' .`）时，**正在执行这次搜索的那个会话文件必然命中自己**：搜索命令本身（连同它的输出）会被实时写进自己的 transcript，于是 pattern 在搜索开始的同一刻已存在于被搜索集合里。结果集必须先剔除当前会话文件（观察者）才能回答"谁提到过 X"；否则"第一个命中/命中总数"里永远含自己一个，命中数类结论直接虚高。

## 为什么

这是观察者效应在**自写入日志目录**上的必然结果，有两个后果：

1. **数量虚高**：命中数 = 真实提及者 + 1（自己）。
2. **无法自证清白**：如果被搜的 pattern 与"取证行为"本身相关（例如某个会话 id、某条命令名、某次崩溃的标识），那么"谁提到过它"的答案里**总是**包含本次取证会话，而这条命中不含任何关于事件的信息。

它还带来一个隐蔽的次序问题：搜索输出被写进 transcript 之后，再搜一次依然命中，且命中处就是上一次的搜索结果——重复取证会把结果集越滚越大。

## 证据（本会话命令 ↔ 结果，切片逐字）

- 命令（在被搜目录内执行，且被搜 pattern 就是命令的一部分）：
  `cd /Users/zodyne/.pi/agent/sessions/--Users-zodyne--/ && echo "=== who mentions 20260910_091413_a643f9 ==="; rg -l '20260910_091413_a643f9' . 2>/dev/n…`
- 结果：`=== who mentions 20260910_091413_a643f9 === ./2026-09-16T00-43-10-128Z_01a0a7aa-e5b0-725c-a75a-f97e671dc5aa.jsonl ./2026`
- **第一个命中就是本会话自己的文件**：`2026-09-16T00-43-10-128Z_01a0a7aa-e5b0-725c-a75a-f97e671dc5aa.jsonl` 与会话头（切片 `session:` 行）指向同一路径、同一 session id；它进入结果集只是因为这条命令与它的输出被记进了自己。

## 反例 / 边界

- 若被搜的 pattern 与本次取证无关（例如搜一段业务代码里的常量），自命中不会发生——判据是"pattern 是否出现在我这条命令里（含 shell 变量展开后的形式）"。本条的适用面是**被搜 pattern 出现在取证动作自身**的场合，这正是"谁提到过这个 id/命令"类问题的常态。
- 修法二选一：①显式排除当前文件（先在输出里认出自己那份 transcript 的文件名/路径，再 `rg -l --glob '!<current>.jsonl'` 或做集合差）；②换判据——不去数"提到过的文件"，而只在**该 pattern 具有执行语义的字段**上匹配（工具调用的命令字段），把"提及"排除掉（见 related 的两条）。
- **别把它修成相反的错**：剔除自己之后剩下的命中仍可能是"正文里的提及"而非执行/发生，数量对不上结论；本条只管"观察者必须排除"，不管"命中是否等于事实"。
- `2>/dev/null` 之类的收尾会把"搜索目录不存在/权限错"一并吞掉，剔除自命中时不要把这类静默失败当成"结果本来就是这些"。

## 失败信号（未来命中即该想起本条）

- 命中清单第一条就是当前会话/当前日志文件，却把它当成一个"提及者"写进结论。
- "谁提到过 X" 的答案里出现本次取证会话自己（它不可能知道 X 的由来，命中只因它在搜 X）。
- 拿 `rg -l | wc -l` 的差 1 结果去论证"有 N 个消费者/引用者"。
