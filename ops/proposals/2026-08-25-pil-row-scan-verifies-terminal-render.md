# 用 PIL 逐行统计把终端截图变成"文本带 + 平均色"表，无视觉通道也能定量核对 TUI 渲染

## 主张
没有看图能力时，终端截图仍可定量分析：`Image.open(p).convert('RGB')` 后**按行扫描**，
统计每行的非背景像素数与平均 RGB，把连续的亮行聚成"文本带"，输出
`[y起-y止] 高度 avg色=(R,G,B) 亮度=L` 的表格。
由此可读出：有几行文本、行高与行距、每行的前景色（进而判断它用的是 muted 还是 accent），
足以验证"布局是否按预期渲染、某段文字是否被染成了指定颜色"。

## 步骤
1. 定位并拷贝截图到可读路径（文件名坑见 macOS 截图条目），`img = Image.open(p).convert('RGB')`，先打印 `img.size`。
2. 先裁剪感兴趣区（如 `img.crop((0, int(h*0.52), w, int(h*0.86)))`）降噪、缩小扫描量。
3. 逐行统计"非背景像素数 + 平均亮度"；亮度阈值按背景来定（近黑背景时背景行平均亮度≈3）。
4. 把连续超阈值的行合并成文本带，输出 `(y 范围, 高度, 平均色, 亮度)`。
5. 若某区域应有内容却空表，**降低阈值重扫该 y 区间**再判断（浅色/低对比文本会被高阈值吃掉）。
6. 拿平均色去对表：与皮肤 YAML / theme 里的 muted / accent / text 值比对，得出"这行用的是哪个 token"。

## 证据（本会话命令对照）
- `Image.open('/tmp/hermes_shot_think.png')` → `size: (3142, 1826)`；裁剪保存 → `crop saved (6284, 1096)` / `(4713, 985)`。
- 背景基线：逐行打印 → `y=0: 44 非背景像素, 平均亮度=3`（连续多行同值，确认近黑背景）。
- 文本带提取：`文本带(y范围): [[0, 7], [56, 75], [124, 143], [158, 177], [236, 237], [327, 349], [396, 415], [463, 485]]`
- 带颜色的全图版本：`共 28 个文本带 (y 范围, 高度, 亮度)` →
  `[346-365] 高19 avg色=(199, 148, 149) 亮度=165`、`[385-399] 高14 avg色=(173, 138, 139) 亮度=150` ...
- 降阈值重扫指定区间：`=== y 1080-1260 ===  [1092-1116] 高24 avg=(155,155,183) 亮度=164 / [1162-1181] 高19 avg=(83,83,89) 亮度=85`
  —— 同一图里亮度 85 的暗色行只有降阈值才出得来。

## 边界 / 反例
- **读不出文字内容**，只给几何与颜色；要确认"写的是什么字"必须另找途径（配置、源码、日志）。
- 平均色是"字形像素 + 抗锯齿边缘"的混合，会比 token 真值偏暗/偏灰；用于**区分**两个 token 够用，
  用于**精确等值断言**不够——判断时留容差、优先比较相对关系（哪一行更亮/更红）。
- 阈值与背景强相关：本次背景亮度≈3，阈值 40 会漏掉暗色行；换主题/浅色背景需重新定标。
- 结论仍是间接证据：截图里"看起来对了"不等于代码路径对了，必要时配合源码/测试交叉验证。
